# SourceTrace 产品与工程规格说明

## 1. 文档状态

- 状态：已确认，作为首版开发基线
- 产品版本：MVP
- 目标用户：需要基于个人资料进行可信问答的单用户
- 项目目标：形成可运行、可评测、可解释的 Agentic RAG 项目，用于 AI 应用开发与
  Agent 开发方向的学习、作品展示和实习面试

本文件描述 SourceTrace 首版必须实现的外部行为和验收标准。`docs/architecture.md`
描述代码边界与技术结构，`docs/roadmap.md` 描述实施顺序。三者冲突时，产品行为以本文件
为准，工程约束以根目录 `AGENTS.md` 为准。GitHub Issue 负责把本规格拆成可执行任务，
不得覆盖本文件中的产品行为；若任务需要改变产品决策，必须在同一个变更中更新本文件和
相关 Issue，评审完成后再实施。

## 2. 产品定义

SourceTrace 是一个面向私有 PDF 资料的、严格基于知识库证据回答的 Agentic RAG 应用。
用户创建命名知识库、上传文档并发起对话。系统必须先检索当前知识库，再判断证据是否
足够；证据充分时给出带页码和原文摘录的回答，证据不足时明确拒答。

核心承诺：

1. 回答中的事实性内容可追溯到当前知识库中的具体文档版本、页码和原文片段。
2. 模型内部知识不能作为事实证据，不能用来补齐知识库中缺失的信息。
3. 文档解析、切分、嵌入、检索和回答均记录版本，使结果可重放和评测。
4. Agent 的价值体现在受约束的检索决策和证据判断，而不是无限自主调用工具。

## 3. 用户与运行边界

### 3.1 首版用户模型

- 首版是单用户本地应用，不实现注册、登录、角色和资源共享。
- 系统支持多个命名知识库，数据必须按知识库隔离。
- 用户进入一个知识库后再创建会话；会话绑定该知识库，后续每轮无需重复选择。
- 后端每次检索仍必须显式使用知识库 ID 过滤，不能只依赖前端上下文。

### 3.2 支持的输入

- 仅支持用户手动上传的文本型 PDF。
- 单文件最大 20 MB，最多 500 页。
- 通过文件签名验证 PDF，不能只信任扩展名或客户端 MIME 类型。
- 拒绝加密或需要密码的 PDF、损坏的 PDF，以及没有可提取文本的扫描件。
- 首版不支持 OCR、Word、网页抓取、图片理解和自动联网采集资料。

### 3.3 演示资料

- 可使用公开的 AI、RAG 或 Agent 方向 PDF 构建固定演示知识库。
- 大模型可以在产品外辅助寻找候选资料，但资料必须由用户确认来源、许可证和内容后
  手动上传。
- 第三方 PDF、模型权重和用户上传内容不受本仓库 MIT License 覆盖，也不得提交到
  Git 仓库。

## 4. 核心用户旅程

### 4.1 管理知识库

用户可以创建、查看列表、查看详情和永久删除知识库。列表必须分页。知识库名称不能为空，
同一用户下的重名策略必须由 API 明确返回，不能静默覆盖。

永久删除知识库属于显式破坏性操作，必须要求用户确认，并清理其文档、文档版本、原文件、
片段、向量、会话和相关回答数据。Redis 中残留的任务消息不能使已删除资源复活。

### 4.2 管理文档和版本

一个逻辑文档可以拥有多个不可变版本：

- 上传内容的校验和与已有版本完全一致时，返回去重结果，不重复存储和摄取。
- 文件名相同但内容变化时，创建新版本，不覆盖旧版本。
- 新检索默认只使用每个逻辑文档的最新可用版本。
- 历史回答保留其生成时引用的旧版本，直到用户执行相关资源的永久删除。
- 版本内容、校验和、解析结果和处理配置一旦进入摄取流程就不可原地修改。

知识库详情页必须展示文档、版本、文件大小、页数、当前摄取阶段、尝试次数、创建时间和
安全的失败原因，并提供符合状态约束的重试或删除操作。

### 4.3 提问与引用

用户在知识库内创建或打开会话并提问。回答语言跟随用户问题，引用中的文档标题和原文摘录
保持原始语言。

每条引用至少包含：

- 稳定引用 ID
- 文档与文档版本 ID
- 文档名称
- PDF 页码
- 原文摘录
- 可访问原文件指定页的链接

首版不要求坐标级高亮或框选。引用点击后应打开对应 PDF 页；若浏览器不支持精确页跳转，
仍必须打开文档并展示目标页码。

### 4.4 对话上下文

- 最近对话历史仅用于代词消解和检索查询改写。
- 每个问题都必须重新检索当前知识库。
- 以前的模型回答不是证据，不能被后续回答直接引用为事实来源。
- 系统持久化会话、问题、最终回答、引用、拒答结果、模型版本、工作流版本和必要耗时。
- 系统不持久化隐藏思维过程，不按 token 写数据库，也不记录完整提示词到日志。

## 5. 文档摄取规格

### 5.1 处理链路

摄取流程为：文件验证、原文件持久化、版本登记、任务投递、PDF 解析、文本切分、嵌入、
向量入库和完成标记。

文本切分成功后版本进入 `chunked` 中间状态；该状态是解析切分任务的终态，但不代表完整
摄取完成，也不得参与检索。只有嵌入与向量入库全部成功后才能标记为 `completed` 并激活
为可检索版本。

PostgreSQL 是文档与任务状态的权威数据源。Redis 只传递文档版本 ID 并承担任务队列，
不能保存唯一业务状态。

### 5.2 PDF 解析

- 首版使用 `pypdf`，并通过 `DocumentParser` 端口隔离。
- 解析结果必须保留 PDF 页码和原始文本。
- 单页无文本可以记录为空；整份文档无可提取文本必须失败并提示 OCR 暂不支持。
- 解析器异常不能留下半完成的可检索版本。
- 复杂布局样本进入契约评测；只有评测证明当前解析器不足时才替换实现。

### 5.3 文本切分

- 片段不得跨越 PDF 页面。
- 使用基于 token 的重叠窗口，初始配置约为每片 500 tokens、重叠 80 tokens。
- 每个片段保存文档版本、页码、页内顺序、原文和稳定 ID。
- 切分大小、重叠大小、分词器和切分算法版本必须配置化并记录在摄取版本中。
- 首版不使用大模型进行语义切分。

### 5.4 本地嵌入

- 默认嵌入模型为 `BAAI/bge-m3`，首版只使用 dense embedding。
- 向量归一化后写入 pgvector，检索使用 cosine distance。
- 模型缓存在宿主机 `D:\DevelopEnvironment\huggingface`，容器 Worker 通过只读或受控
  bind mount 复用缓存，不把模型复制进 Git 或 Docker 镜像。
- Hugging Face 缓存位置通过统一环境配置设置，不能散落硬编码在业务代码中。
- Worker 的 CPU 与 CUDA 启动方式使用同一份业务代码；GPU 由独立 Compose override
  启用。

### 5.5 队列、幂等和失败

- 使用 Dramatiq 与 Redis 执行摄取任务。
- 幂等键至少包含文档版本和处理阶段；重复投递不得产生重复片段或向量。
- 数据库记录当前阶段、尝试次数和脱敏后的错误信息。
- 数据库、Redis 暂时不可用或模型加载失败属于可重试错误，最多自动尝试 3 次并退避。
- 加密、损坏、超限或无可提取文本属于永久错误，不自动重试。
- 自动重试耗尽后允许用户手动重试；手动重试仍遵守幂等约束。
- 前端每 2 秒轮询摄取状态，直到进入完成或失败终态。

## 6. 检索与 Agent 工作流

### 6.1 检索基线

- 查询嵌入使用与文档一致的 BGE-M3 dense embedding 和归一化策略。
- 在当前知识库与最新可用文档版本范围内执行 pgvector cosine 检索。
- 最终主候选数量最多为 8，并通过统一配置管理。检索先读取一个有界的 dense 候选池，再按
  cosine 相似度顺序优先选择不同 `(document_version_id, page_number)` 的候选；不同页面不足
  8 个时，才按原始相似度顺序补入同页候选。
- 为避免切分边界造成的证据截断，初始召回后可补入每个命中片段同页的有限相邻片段；这不是
  增加 dense top-k，补入片段继承触发片段的检索分数，并与原始候选一同接受后续证据门禁。
- 首版不加入 BM25、稀疏检索或 reranker。只有版本化评测证明召回不足时再引入。

### 6.2 LangGraph 状态机

LangGraph 是首版 Agent 编排核心。固定工作流为：

1. 分析问题并生成检索计划。
2. 调用受知识库范围约束的检索工具。
3. 判断证据是否充分并选择候选片段 ID。
4. 若证据不足且尚未补充检索，改写查询并最多再检索一次。
5. 证据充分时，仅基于选中片段生成带引用回答。
6. 证据不足或引用校验失败时明确拒答。

首版不接入 Dify 或 Coze，不提供可视化工作流编辑器，不允许 Agent 任意循环或访问未授权
知识源。

### 6.3 证据门禁

回答必须依次通过以下门禁：

1. 检索结果达到可配置的最低相关性和有效片段要求。
2. Agent 以结构化输出声明证据是否充分，并返回所选片段 ID。
3. 回答生成器只能接收所选片段作为事实上下文。
4. 确定性校验器确认所有引用存在、属于当前知识库并来自本次允许的文档版本。
5. 校验失败时允许修复一次；仍失败则拒答，不能返回无引用的降级答案。

阈值必须使用用户审核过的版本化评测集校准，不能凭演示效果宣称准确率。

### 6.4 模型供应商

- 回答模型通过 OpenAI API 兼容适配器接入中转站。
- 暂定模型别名为 `gpt-5.6-luna`，必须配置化；该名称只代表中转站别名，不宣称其
  对应任何官方固定能力。
- 接入前必须通过能力探测验证流式响应、结构化输出、超时、取消和错误格式。
- API 密钥只通过服务端环境变量注入，不提交仓库、不写入前端、不在日志中输出。
- 模型供应商必须位于 port 后面，测试使用确定性 fake，不依赖真实中转站。

## 7. 回答流、并发与取消

### 7.1 SSE

- 回答通过 POST 请求返回 `text/event-stream`，Vue 使用流式 `fetch` 消费。
- SSE 事件 schema 必须版本化，至少区分运行状态、文本增量、最终结果、拒答、取消和错误。
- 最终结果事件包含完整回答和引用；文本增量不能被当作已持久化的最终回答。
- 首版不使用 WebSocket。

### 7.2 Answer run 状态

每次提问创建独立 `answer_run`，状态至少包括：`pending`、`running`、
`cancel_requested`、`cancelled`、`completed` 和 `failed`。

- 同一会话同一时间只允许一个活动 run。
- 不同会话可以独立运行。
- 用户取消时，前端通过 `AbortController` 停止读取，并调用显式取消接口。
- LangGraph 在节点边界检查取消状态，并尽力关闭上游模型流。
- 已输出的部分文本不得保存为最终答案，也不得进入后续对话上下文。
- 用户在同一会话发起新问题时，前端必须先取消或等待当前 run 进入终态，不能静默并发。

## 8. 前端范围

首版包含以下页面和能力：

- 知识库列表、创建和永久删除。
- 知识库详情、PDF 上传、文档版本、摄取状态、失败原因和重试。
- 问答页面、流式回答、拒答状态、页码引用、原文摘录和取消操作。
- 会话列表与历史问答查看。

首版不包含登录注册、个人资料、管理后台、模型市场、工作流编辑器、在线 API Key 配置、
自动网页抓取和演示视频。

## 9. 数据与可重放性

核心实体包括：

- `KnowledgeBase`
- `Document`
- `DocumentVersion`
- `IngestionRun`
- `Chunk`
- `Conversation`
- `Question`
- `AnswerRun`
- `Citation`

公开资源使用 UUID，时间统一保存为带时区 UTC。数据库迁移只通过 Alembic。每次摄取和回答
必须能关联到所使用的解析器、切分、嵌入、检索、提示词、工作流和模型版本，但不保存模型
隐藏推理。

## 10. 评测规格

### 10.1 测试接缝

- 主要接缝是公开 HTTP 与 SSE 接口。集成测试使用与前端相同的请求验证知识库、文档、
  会话、引用、拒答和取消等用户可观察行为，不断言 Router、Service 或 Repository 的
  内部调用次数。
- Worker 任务接口是异步处理接缝。测试输入文档版本 ID，使用真实测试数据库和可控的
  解析、嵌入适配器，验证幂等、重试、失败分类和最终片段。
- LangGraph 工作流接口是回答决策接缝。测试输入问题、知识库范围和 run 状态，使用
  确定性的检索与模型适配器，验证补充检索、证据门禁、引用校验、拒答和取消。
- pypdf、OpenAI 兼容供应商与 BGE-M3 分别通过窄契约测试验证页码、流式协议、错误映射、
  向量维度和归一化等接口行为。
- 前端沿用共享 API client 测试，并通过页面级用户行为测试覆盖关键旅程。

### 10.2 RAG 评测集

- 首个评测集目标约 30 个由用户人工审核的样本。
- 样本覆盖直接命中、多片段综合、无法回答和高混淆问题。
- 每个样本记录问题、参考答案或拒答标签、知识库版本、证据文档和页码。
- 分开评测检索召回、引用正确性、拒答行为和端到端结果，不用单一主观分数代替。
- 所有结果绑定评测集、配置和代码版本；未实际运行不得填写指标。
- 外部模型使用真实适配器进行受控评测，常规自动化测试使用 fake。

## 11. 部署与仓库规范

### 11.1 开发和最终运行

- 日常开发：PostgreSQL 与 Redis 在 Docker 中运行，API、Web 和 Worker 可在宿主机运行，
  便于断点调试。
- 最终交付：Web、API、Worker、PostgreSQL 和 Redis 均可通过 Docker Compose 启动。
- 基础 Compose 保持 CPU 和跨机器可移植；GPU Worker 使用单独 override 文件。
- Docker 镜像只包含代码和运行依赖，不包含密钥、数据库卷、上传 PDF 或模型缓存。

### 11.2 GitHub

- 公开仓库采用 MIT License。
- 提交 Dockerfile、Compose、`.dockerignore` 和 `.env.example`；不提交 `.env`、模型、
  数据库数据、上传文件和构建产物。
- 每个里程碑使用独立功能分支，完成检查和文档后再合并到 `main`。
- 提交按可验证功能拆分，避免一次提交整个项目。
- 代码标识符、API 字段和提交信息使用英文；README 以中文为主并提供简短英文简介。

## 12. 质量与安全要求

- 后端遵守 `router -> service -> repository` 单向依赖，外部系统置于 port 后面。
- Python 通过 Ruff 和 mypy strict；TypeScript 保持 strict。
- API 错误使用统一 Problem Details 并携带请求 ID。
- 日志不得记录令牌、完整 PDF 内容、完整提示词或隐藏推理。
- 所有列表分页，所有 API 输入在边界校验，所有 Redis 缓存设置 TTL。
- API 契约变化后重新生成并提交 Web OpenAPI 类型。
- 业务规则需要单元测试；数据库、HTTP 和适配器边界按风险增加集成或契约测试。
- 每个缺陷修复必须包含一个先前会失败的回归测试。

## 13. 实施里程碑与验收

### 里程碑 1：知识库与文档版本基础

范围：数据库实体与 Alembic 迁移、知识库 CRUD、文档和不可变版本的领域规则及对应 API，
但不执行 PDF 解析、向量检索或模型调用。

验收条件：

- 知识库可创建、分页查询、查看和永久删除。
- 文档版本能表达校验和去重、同名新版本和最新版本选择规则。
- 资源使用 UUID 和 UTC 时间，外键删除行为明确。
- Router、Service、Repository 边界符合架构约束。
- 单元、数据库集成、OpenAPI 契约、静态检查和前端类型生成通过。

### 里程碑 2：异步摄取闭环

范围：PDF 上传、文件验证、Dramatiq、Worker、pypdf 解析、分页切分、BGE-M3、pgvector
写入、状态轮询和手动重试。

验收条件：

- 合法 PDF 最终进入可检索状态，非法文件得到明确且安全的错误。
- 同一版本任务重复执行不产生重复片段或向量。
- 暂时故障按策略重试，永久故障不自动重试，耗尽后可手动重试。
- 页面可查看版本、阶段、尝试次数和失败原因。

### 里程碑 3：可追溯流式问答

范围：pgvector 检索、会话历史、SSE、回答生成、引用跳转、拒答、run 状态和取消。

验收条件：

- 每轮检索严格限制在会话绑定的知识库和允许的文档版本。
- 完成的回答包含可验证引用，点击可打开对应 PDF 页。
- 证据不足时返回结构化拒答，不输出基于模型内部知识的答案。
- 取消后 run 进入正确终态，部分文本不成为最终答案；同会话不能并发运行。

### 里程碑 4：受约束 Agent 与评测

范围：LangGraph 工作流、一次补充检索、证据门禁、引用修复、版本化评测集、最终文档与
代码讲解。

验收条件：

- 工作流按固定节点运行，最多进行一次补充检索且可观察、可取消。
- 伪造、越界或不存在的引用被确定性校验拒绝。
- 人工审核的评测集能重放，并按版本输出检索、引用和拒答结果。
- README 能让新环境完成本地混合运行和全 Docker 运行。
- 用户能够解释核心代码路径、关键技术原理、遇到的问题及解决方式。

## 14. 阶段验收流程

每个里程碑完成后暂停后续开发，并交付：

1. 可运行功能和实际检查结果。
2. 本阶段代码结构与关键调用链讲解。
3. 实际遇到的问题、定位过程和解决方案。
4. 相关技术原理及可能的面试追问。
5. 对应 Git 提交和更新后的阶段文档。

只有用户理解并明确验收当前阶段后，才进入下一里程碑。

## 15. 首版之外

认证授权、多人协作、OCR、Word 和网页摄取、混合检索、reranker、对象存储、生产监控、
配额、速率限制与云端公开部署均不属于首版承诺。它们只能在核心闭环完成并由评测或部署
需求证明必要后进入后续规划。

## 16. 实施前后需要验证的参数

以下内容是已接受的初始方案，不是已经测得的结论：

- `gpt-5.6-luna` 是否支持所需的 SSE 流式输出、结构化输出和主动取消。
- BGE-M3 在目标机器的 CPU、CUDA 和容器环境中的加载方式、显存占用与稳定性。
- 每片约 500 tokens、重叠 80 tokens、召回 8 个片段是否适合最终演示语料。
- 证据充分性、最低相关性和拒答门禁的具体阈值。
- 中转站的速率限制、错误格式、超时行为和模型别名稳定性。

这些参数必须通过适配器契约测试、实际硬件 smoke test 和版本化评测集确定。调整参数不改变
产品的不变量：只使用知识库证据、引用必须可验证、证据不足必须拒答。
