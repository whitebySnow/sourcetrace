# 0003: 为多证据问题采用有界证据槽位查询规划

状态：accepted，候选覆盖配额部分由 0006 部分替代
日期：2026-08-08

## 背景

ADR 0001 禁止初始规划器拆分比较、归属和组合问题。当时的真实探针表明，无约束的模型查询会
猜错论文归属，并在统一重排和固定 Top 8 中挤掉原问题已经命中的证据。随后生产检索增加了
文档标题约束、逐查询 reranker、查询覆盖候选、有界 PostgreSQL lexical 通道和完整逐查询
轨迹，原有风险已经具备独立控制手段。

Issue #52 后的固定 30 题生产 repository 重放仍有 `ARF-024` 与 `ARF-026` 两个多证据问题
失败。两题都只执行原问题：前者需要分别覆盖原始 RAG 与 Self-RAG 的检索时机，后者需要覆盖
RAG、ReAct 与 Self-RAG 的组件归属。只替换查询计划的两题探针在不改变 embedding、候选池、
reranker、最终 Top 8、cosine 门禁或证据规则时使两题通过，说明缺失的是证据槽位查询，而不是
更宽的检索预算。

## 决定

`QuestionPlanner` 保持现有接口，继续只接收当前问题、最近用户问题和最多 50 个当前可检索
文档标题。它按以下规则返回零至两条额外查询：

1. 原始问题始终由 `RetrievalService` 作为第一条查询执行，规划器不能替换它。
2. 对明确要求比较多个方法，或把多个命名实体、术语、组件分别归属的多证据问题，规划器可将
   问题拆成最多两个证据槽位查询。每条查询只针对一个可命名槽位，并保留问题中的实体、逻辑
   极性和英文技术词。
3. 对需要主动搜索限制或失败模式的绝对化、否定性声明，规划器仍最多生成一条反例查询。
4. 简单事实题和无法识别稳定槽位的问题不生成额外查询。不得为了用满预算生成宽泛关键词、
   完整答案、结论或没有问题锚点的论文摘要请求。
5. 文档标题只能约束方法别名和论文归属。模型知识与生成查询仍只是检索假设，不能作为回答
   事实或引用；规划阶段不读取或发送 PDF 正文、预期答案和评测证据。
6. `RetrievalService` 对所有查询规范化去重，并继续强制整个 Answer Run 最多两条额外查询。
   单次补充检索轮次可一次消费全部剩余额度：初始规划未使用额外查询时最多接受两条，使用
   一条时最多接受一条，使用两条时不再允许补充查询。
7. 第一阶段得到多槽位计划后，规划器对最终选中的每个槽位分别执行一次独立细化。每次细化只
   接收当前问题、最近用户问题、可检索文档标题和第一阶段为该槽生成的查询与文档标题；不读取
   检索候选、PDF 正文、答案、评测证据或标签。各槽细化并发执行，因此最多增加一个串行供应商
   往返。细化结果不得改变文档标题、增加槽位或合并槽位；无效结果对应的槽位被丢弃。单槽反例
   计划与简单事实题不进入细化阶段。
8. 初始计划存在无法验证的重复文档归属时，纠错后仍无效则整体回退，不从语义冲突的响应中
   猜测性保留槽位。证据不足后的补充查询每条只覆盖一个缺失组件，不得加入问题或候选证据尚未
   建立的论文、方法、框架或组件归属；多个缺口在剩余额度内分别查询。

每条查询继续经过相同的有界 dense 与 lexical 通道、逐查询 reranker 和覆盖选择。原问题最多
贡献四个覆盖候选；额外查询的覆盖配额由 ADR 0006 定义。最终主证据、最低 cosine、证据充分性、
拒答和引用门禁均不改变。规划提示词和 Retrieval Plan 版本升级，历史 Answer Run 保留旧版本语义。

本决策只替代 ADR 0001 中“初始规划器至多一条查询，且比较、归属和组合题必须保持单查询”的
部分。ADR 0001 的标题范围、查询覆盖、总预算、逐查询重排和可重放要求继续有效。

## 替代方案

1. 保持原问题单查询：无法同时为多个文档或组件保留目标证据，已由两题失败轨迹否决。
2. 放宽 Top 8、Top 32 或 cosine 门禁：会扩大所有问题的成本或噪声，且探针证明无需放宽。
3. 为每个实体生成一条查询：`ARF-026` 可产生四条以上查询，违反现有延迟与可重放预算。
4. 让证据评估器在首次失败后逐槽位自由循环：增加不可控模型调用和状态空间，不符合有界工作流。
5. 在 Service 中实现方法名或论文名硬编码：只能通过当前评测题，不能形成产品能力。

## 后果

- 规划器结构化响应上限从一条变为两条，纠错提示和供应商契约测试同步更新；多槽问题最多产生
  一次槽位识别调用和两次并发细化调用。
- 比较与组合题最多执行三次有界检索和 reranker 调用；总查询上限不变，因此最坏成本不增加。
- 初始计划可能耗尽补充查询预算，工作流必须从计划长度计算是否仍允许补检。
- 查询质量仍可能导致回退；采用前必须把真实规划器输出版本化，并重放完整 30 题确认现有
  25 个检索通过项不退化。
- `ARF-024` 与 `ARF-026` 的探针只证明设计方向，不构成端到端回答准确率结果。

候选覆盖配额的固定“每条额外查询一个”规则已由 ADR 0006 替代；本 ADR 的其余查询规划、
两条额外查询预算、槽位细化和可重放要求继续有效。
