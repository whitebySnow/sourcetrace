# 0001: 用文档标题约束查询规划并按查询重排候选

状态：accepted，候选覆盖配额部分由 0006 部分替代
日期：2026-08-07

## 背景

固定 30 题生产评测中，复杂对比题、组合题和反例题仍有四个 dense 检索失败。诊断证明目标
文本存在于正确的 PDF 页和 Chunk 中，但仅用原始问题统一重排融合候选，会压低只支持某个
子问题的片段。真实供应商探针还表明，只向规划器提供问题和最近问题时，模型可能猜错论文归属，
例如把知识库中组件关联到不存在于当前语料的框架。

继续调整阈值、扩大最终 Top-8 或接受模型猜测都会破坏严格证据策略。把额外查询上限改为无限
也会损害延迟、成本和可重放性。

## 决定

`RetrievalService` 保持查询规划、候选融合和重排的深模块接口。工作流在解析计划时提供
Knowledge Base ID、当前问题和最近问题；模块内部通过 retrieval repository 读取最多 50 个
当前可检索文档标题，并把稳定排序后的标题作为可选规划上下文传给 `QuestionPlanner`。

标题只用于形成论文名称、方法别名和组件归属等检索假设。规划阶段不读取文档正文；标题、补充
查询和模型知识均不能成为回答事实或 Citation。完整标题列表和规划提示词不得写入日志。

原始问题仍必选。初始规划器固定使用 `temperature=0`，只为绝对化或否定性声明生成最多一条
搜索限制或失败模式的反例查询；简单事实、对比、归属和组合题保持原始问题作为初始计划。
证据评估后的单次补检可使用剩余查询额度，整个 Answer Run 仍最多执行两条额外查询。
每条查询分别读取原有大小的 dense
候选池，并由 BGE cross-encoder 针对产生该候选池的查询重排。原始问题最多贡献四个覆盖候选，
每条模型生成的额外查询最多贡献一个；候选去重后，覆盖候选优先，再用候选在各查询中的最高
reranker 分数补足其余位置。两组内部都
依次用最高 reranker 分数、RRF 分数、最佳 cosine 分数和 Chunk UUID 稳定排序。最终主证据仍
最多八个，并继续执行页面多样性和同页邻接扩展。

轨迹保存逐查询候选的 cosine 排名、reranker 分数、逐查询重排排名和覆盖标记，以及融合候选
的最高 reranker 分数、最终排名和主证据标记，使结果可重放。任何查询的重排失败都会使本轮
检索失败，不得回退到未重排结果。

## 替代方案

1. 让初始规划器自动拆分所有复杂问题：真实 DeepSeek 探针在比较和组合题上生成的查询会挤掉
   原问题的有效证据，因此在没有查询意图和文档范围约束前不采用。
2. 把所有候选继续只按原始问题重排：会系统性压低只支持单个子问题的正确证据。
3. 增加 BM25 或 BGE-M3 sparse 通道：成熟方案可行，但会同时改变召回通道和索引契约，留待
   独立 A/B Issue。
4. 把额外查询上限提高到四条：与当前产品预算冲突，并增加延迟和候选竞争。

## 后果

- 规划器能看到有限的知识库文档标题，因此外部模型供应商会接收这些元数据；部署者应把它们
  视为与回答证据相同级别的外发数据。
- `QuestionPlanner` 和 retrieval repository 接口各增加一个参数或方法，但标题读取、排序和
  覆盖算法不泄漏到工作流。
- 每个复杂问题最多执行三次有界 reranker 调用，计算量与现有最多三条查询一致，但调用批次从
  一个融合批次变为逐查询批次。
- 原始问题拥有更高覆盖预算；初始模型扩展只处理已通过版本化评测验证的反例检索模式，避免
  比较和组合题中的推测性查询使既有直接证据回退。
- 检索配置、规划提示词和轨迹 schema 必须升级版本；历史运行继续保留旧版本语义。
- 是否引入混合召回仍由后续固定数据集 A/B 决定，本决策不授权 BM25、稀疏索引、阈值放宽或
  证据门禁变化。

候选覆盖配额的固定“每条额外查询一个”规则已由 ADR 0006 替代；本 ADR 的其余查询范围、
逐查询重排、最终 Top-8 和可重放要求继续有效。
