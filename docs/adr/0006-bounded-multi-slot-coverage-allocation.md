# 0006: 在固定 Top-8 内为多槽位查询分配覆盖候选

状态：accepted
日期：2026-08-15

## 背景

ADR 0001 将每条额外查询的覆盖候选固定为一个，以防推测性扩展挤占原始问题的直接证据。
`ARF-026` 的本地可重复诊断显示，ReAct 槽位查询已召回满足最低 cosine 门槛的规范证据，
但该片段在该查询的 reranker 排名为第二。固定一个覆盖候选使它在全局融合与页面选择之前
被丢弃，即使默认 Top-8 仍有容量。

这不是扩大候选池、降低相似度阈值或放宽证据门禁的问题。目标是保留多槽位查询中紧随第一名的
有效证据，同时保持原始问题优先、总查询预算和最终证据上限。

## 决定

`RetrievalService` 继续为原始问题保留最多四个覆盖候选，且所有覆盖配额之和不得超过实际
Top-K。对实际有候选的查询，模块先给每条查询一个覆盖候选；再优先把剩余容量分给原始问题，
直到它达到四个；最后按额外槽位查询顺序分配第二个候选，每槽最多两个。因此默认 Top-8 且恰有
两个额外槽位时，原始问题与两个槽位分别最多保留四、二、二个候选。

较小的 Top-K 会在不超出最终容量的前提下保留所有可用查询的第一条候选，余量才优先给原始问题。
覆盖候选仍优先于其他融合候选，之后继续按最高逐查询 reranker 分数、RRF、原始 cosine 和
Chunk UUID 排序，并执行原有页面多样性选择。

本决策只替代 ADR 0001 中“每条模型生成的额外查询最多贡献一个覆盖候选”的配额规则；原始
问题优先、最多两条额外查询、候选池大小、最终 Top-8、最低 cosine、证据充分性、Citation 和
Refusal 门禁全部不变。

## 替代方案

1. 针对 ReAct 或评测 case 硬编码额外查询或候选：只会掩盖当前样本，不能形成可泛化能力。
2. 扩大最终 Top-8 或单查询候选池：会增加所有请求的上下文、成本或噪声，且并非本次缺失原因。
3. 取消原始问题的更高覆盖配额：会重新引入推测性扩展挤掉用户原始意图的回归风险。
4. 让 Evidence Assessor 在缺失证据时放宽拒答：会违反严格基于知识库证据的产品不变量。

## 后果

- 默认双槽位计划最多把八个覆盖候选前置，仍受页面多样性和最终 Top-8 限制。
- 单槽位与低 Top-K 路径保持原始问题优先，且覆盖配额绝不超过最终证据容量。
- 检索配置版本必须升级；新的本地混合检索报告绑定新版本，历史报告继续保留旧语义。
- 单元测试必须覆盖额外槽位第 2 名的证据保留；接入前必须在版本化 30 题本地回放中检查回归。
