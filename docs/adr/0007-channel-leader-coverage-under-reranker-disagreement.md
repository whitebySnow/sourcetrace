# 0007: 在额外槽位覆盖中保留通道融合首位

状态：accepted
日期：2026-08-17

## 背景

固定 `4/2/2` 覆盖配额能在不扩大最终 Top-8 的前提下保留多槽位查询的第二名 reranker 候选。
但是，绑定的检索阶段诊断显示，交叉编码器可能把已在 dense 与 lexical 通道融合中领先的片段
降到该槽位的覆盖范围外。仅按 reranker 前两名分配额外槽位的两个名额，会使独立通道信号完全
失去进入主证据的机会。

## 决定

保留 ADR 0006 的查询预算、`4/2/2` 配额、原始问题优先和最终 Top-8。原始问题的覆盖候选
继续按逐查询 reranker 排名取得。

当额外槽位拥有两个覆盖名额时，第一个名额给 reranker 首位，第二个名额给通道融合首位。若两者
是同一 Chunk，第二个名额回退给下一名 reranker。所有选择只使用该次检索运行已有的 reranker
排名、通道融合排名和 Chunk ID；不得读取评测数据、预期证据、问题答案或文档正文以偏向某个
样本。

覆盖候选进入后续全局排序时，仍按最高逐查询 reranker 分数、RRF、原始 cosine 和 Chunk UUID
排序，再交给既有页面多样性选择。该决定不改变候选池、最低 cosine、页面邻居、Evidence
Assessment、Citation 或 Refusal 门禁。

## 替代方案

1. 增加每槽位的覆盖名额或最终 Top-8：扩大上下文并违反已有边界。
2. 取消 reranker：丢失已有的 cross-encoder 排序收益。
3. 使用 Dataset 期望 Chunk 或 case ID：会把评测真值泄漏到产品运行时。
4. 只按通道融合排名选择：会让一个通道覆盖完全取代语义重排。

## 后果

- 每个有两个覆盖名额的额外槽位保留两个独立的运行时相关性信号。
- reranker 与通道融合首位相同的常见路径保持原有 reranker 前二语义。
- 检索配置版本必须升级，并以完整版本化本地回放验证没有旧通过项回归。
- ADR 0006 仍定义配额和原始问题优先；本 ADR 只替代其额外槽位第二名的选择规则。
