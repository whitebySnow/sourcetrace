# 实施路线图

路线图按可演示的纵向能力排序，不按“先写完所有数据库层、再写所有接口层”推进。

## 阶段 0：工程基线

- API 与 Web 可独立启动并通过健康检查。
- PostgreSQL/pgvector、Redis 和 Alembic 可用于本地开发。
- Ruff、mypy、Vitest、构建和 CI 形成质量门禁。
- OpenAPI 类型能稳定生成到 Web。

## 阶段 1：文档摄取闭环

- 创建知识库并上传受支持的文档。
- 记录文档版本、校验和、存储键及摄取状态。
- Worker 幂等执行解析、切分、嵌入和入库。
- 页面展示进度、失败原因并支持安全重试。

验收标准：同一版本任务重复执行不产生重复片段；失败可恢复；原文页码或位置可保留。

## 阶段 2：可追溯问答

- 检索、重排并组装有稳定引用 ID 的证据集合。
- 通过 SSE 输出回答事件和最终引用。
- 实现证据阈值与明确拒答状态。
- 用户可从答案引用跳转到原文位置。

验收标准：每个事实性声明有可解析引用；引用内容属于当前知识库；证据不足不会生成
无来源回答。

## 阶段 3：评测与可观测性

- 建立去敏、版本化的检索与回答评测集。
- 分离检索指标、引用正确性、拒答质量和端到端延迟。
- 记录模型、提示词、切分和索引版本，支持结果重放。
- 建立任务失败率、队列积压和外部供应商错误监控。

## 阶段 4：权限与生产加固

- 根据部署场景选择会话或 OIDC，并实现资源级授权。
- 对象存储、内容扫描、配额、速率限制和审计日志。
- 备份恢复、滚动迁移、密钥轮换和数据删除流程。
- 使用真实负载评测容量，再决定是否拆分服务。

## 暂不实现

- 未经测量的微服务拆分和多模型路由平台。
- 用 Redis 代替权威业务数据库。
- 在没有评测集时宣称检索或回答效果指标。
- 与核心闭环无关的复杂管理后台和插件系统。
