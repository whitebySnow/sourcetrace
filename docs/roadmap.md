# 实施路线图

本路线图只定义实施顺序。完整产品行为、技术选择与验收条件以
[`docs/specification.md`](specification.md) 为准。

路线图按可验证的纵向能力推进。每个里程碑使用独立功能分支，完成测试、文档和代码讲解，
经用户验收后才进入下一阶段。

## 已完成：工程基线

- API 与 Web 可独立启动并通过健康检查。
- PostgreSQL/pgvector、Redis 和 Alembic 可用于本地开发。
- Ruff、mypy、Vitest、构建和 CI 形成质量门禁。
- OpenAPI 类型能稳定生成到 Web。
- 统一配置、Problem Details、请求 ID 和基础安全响应头已经建立。

## 已完成：里程碑 1，知识库与文档版本基础

- 建立知识库、文档和不可变文档版本的数据模型与 Alembic 迁移。
- 实现知识库 CRUD、分页和永久删除。
- 实现校验和去重、同名新版本和最新版本选择规则。
- 补充单元测试、数据库集成测试、OpenAPI 契约和前端生成类型。

## 已完成：里程碑 2，异步摄取闭环

- 上传并验证文本型 PDF，持久化原文件和版本信息。
- 使用 Dramatiq 与 Redis 投递任务，Worker 幂等执行处理。
- 使用 pypdf 分页解析并按 token 重叠切分。
- 使用本地 BGE-M3 生成 dense embedding 并写入 pgvector。
- 页面展示摄取状态、失败原因和安全重试操作。

## 已完成：里程碑 3，可追溯流式问答

- 实现知识库范围内的 pgvector 检索和会话历史。
- 通过 SSE 输出回答状态、文本增量、最终引用、拒答和错误。
- 实现引用校验、PDF 页跳转、answer run 状态和主动取消。
- 确保证据不足时拒答，同一会话不并发回答。

## 功能已实现、验收收尾中：里程碑 4，受约束 Agent 与评测

- 使用 LangGraph 实现问题分析、检索、证据判断和至多一次补充检索。
- 实现结构化证据选择、回答约束、引用修复和最终拒答门禁。
- 建立约 30 条由用户审核的版本化评测样本并支持重放。
- 完成全 Docker 运行、README、代码 Walkthrough 和面试材料初稿；用户独立讲解验收仍属于
  当前收尾。

## 当前收尾

- 在当前实现上运行版本化 30 题真实 DeepSeek 回归，并完成必要的人工审核。
- 将评测报告绑定 Dataset、Git commit、模型、提示词、检索配置和 SHA-256；不得复用旧 judgment。
- 通过 CI 后重跑完整 Docker Compose MVP 旅程，验证摄取、问答、Citation、Refusal、
  Cancellation 和重启恢复。
- 完成用户可独立讲解的代码验收；这属于简历准备，不改变产品功能完成状态。

供应商 connect/read timeout 与应用总 deadline 的拆分属于后续独立改进，不阻塞当前严格拒答
MVP，但不能与本轮引用稳定性验收混在同一结论中。

## 暂不实现

- 认证、多人协作、复杂权限和管理后台。
- OCR、Word、网页自动采集和联网搜索工具。
- Dify、Coze、可视化工作流编辑器和多模型路由平台。
- 没有评测依据的 BGE-M3 sparse、外部搜索服务或微服务拆分。
- 云端公开演示和演示视频。
